# Step 7 — Deprecated Code & AI Artifacts

## Goal
Remove provably dead legacy code, dead feature flags, placeholder logic, and AI-generated artifacts. Rewrite surviving comments to explain WHY, not WHAT. If unsure whether something is still needed → report only, never delete.

---

## Detect

### Dead Feature Flags
```bash
# Ruby: constants hard-coded to false
grep -rn "= false\|= 'false'\|= \"false\"" app/ config/ --include="*.rb" | grep -iE "enable|feature|flag|toggle"

# Ruby: ENV check that always evaluates false
grep -rn "ENV\[.*\] == 'false'\|ENV\.fetch.*'false'" app/ config/ --include="*.rb"

# JS/TS: feature flags hard-coded
grep -rn "const.*= false\|FEATURE_.*= false" src/ --include="*.ts" | grep -iE "enable|feature|flag"

# Find all usages of the flag to confirm nothing activates it
FLAG="ENABLE_LEGACY_FLOW"
grep -rn "$FLAG" app/ config/ spec/ --include="*.rb"
```

### Placeholder / AI-Generated Logic
```bash
# raise NotImplementedError
grep -rn "NotImplementedError\|raise 'Not implemented'\|raise \"Not implemented\"\|TODO: implement" app/ lib/ --include="*.rb"

# JS: throw new Error('not implemented')
grep -rn "throw new Error.*implement\|TODO:.*implement" src/ --include="*.ts"

# AI artifact markers
grep -rn "# AI generated\|# Generated by\|# TODO: remove\|# FIXME:" app/ lib/ --include="*.rb"
grep -rn "// AI generated\|// TODO: remove\|// FIXME:" src/ --include="*.ts"
```

### TODO / FIXME Chains
```bash
# Sequential TODOs (3+ in same file)
grep -rn "TODO\|FIXME" app/ lib/ src/ --include="*.rb" --include="*.ts" | \
  awk -F: '{print $1}' | sort | uniq -c | sort -rn | head -20
```

### Narrative Comments (Describe History, Not Intent)
Patterns to look for in comments:
- "I added this because..."
- "This was changed in [date/sprint/PR]"
- "We used to do X, now we do Y"
- "Temporary fix for..."
- "Legacy from the old [system/team/approach]"
- "This was breaking so..."

```bash
grep -rn "I added\|we used to\|changed in\|temporary fix\|legacy from\|was breaking" app/ lib/ src/ --include="*.rb" --include="*.ts"
```

## Classify

### HIGH — Apply (Delete / Rewrite)

**Delete:**
- Feature flag constant hard-coded to `false` with zero usages that set it to `true`
- `raise NotImplementedError` in a method with zero callers (confirmed dead method)
- `# TODO: remove after X` where X has clearly happened (dated, or the referenced feature is shipped)
- Comment blocks that describe git history (who added what, when, why at that time)

**Rewrite:**
- Narrative comment → intent comment (WHY this code exists, not the story of how it got here)

### MEDIUM — Report Only
- Feature flag with mixed `true`/`false` usage (still runtime-configurable)
- TODO without a date or ticket — might be current work
- `raise NotImplementedError` in a method that IS reachable (even if rarely called)
- Comment that's partially narrative but partially explains a non-obvious invariant
- Dead code path behind a flag where the flag is false in ENV but might be set in production

### LOW — Skip
- Any flag where there's doubt about its current state in production
- Code behind a flag that's false locally but unknown in production environment
- Placeholder logic in a file that's being actively developed

---

## Comment Rewrite Rules

**Delete if:**
- Comment describes WHAT the code does (the code itself says that)
- Comment describes the history ("added in sprint 4")
- Comment attributes authorship ("John added this")

**Rewrite if:**
- Comment partially explains a constraint but includes narrative filler

**Keep as-is if:**
- Comment explains a non-obvious invariant
- Comment documents a workaround for a specific external bug
- Comment explains why a counter-intuitive approach is correct

**Rewrite pattern:**
```ruby
# Before (narrative):
# I added this in December because the broker API started returning null prices
# after the maintenance window. The || 0 prevents the downstream crash.
price = raw_price || 0

# After (intent):
# Broker API returns null during maintenance windows — treat as zero to prevent downstream crash.
price = raw_price || 0
```

## Feature Flag Removal Procedure

Before removing a flag and all its branches:

1. Confirm the flag is hard-coded false (not ENV-dependent):
   ```bash
   grep -rn "FEATURE_FLAG" config/ app/ | grep -v "# "
   ```

2. Confirm no test sets it to true:
   ```bash
   grep -rn "FEATURE_FLAG.*true\|stub.*FEATURE_FLAG" spec/ test/
   ```

3. Remove the flag constant and the `if FEATURE_FLAG` branch (keep the non-flag path)

4. Remove any dead code that only ran when flag was true

5. Run post-checklist

---

## Apply (HIGH only)

For each confirmed dead flag:
1. Remove the constant definition
2. Remove all `if FLAG` / `unless FLAG` branches — keep the code that runs when flag is false (the active path)
3. Remove any code that ONLY ran when flag was true
4. Update any spec that referenced the flag
